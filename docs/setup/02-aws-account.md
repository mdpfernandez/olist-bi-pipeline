# 02 — AWS account: from zero to a working CLI

By the end of this guide you will have:

1. An AWS account in the free tier.
2. The root user secured with MFA.
3. A dedicated IAM user (`olist-portfolio-dev`) with the right permissions.
4. AWS CLI configured locally with that user's credentials, under a named profile.
5. Three budget alerts set up ($5 / $20 / $50) so you get an email if anything starts costing more than expected.

> **Reading time:** ~10 min. **Active time:** ~40–50 min.
>
> **Heads up:** AWS will ask for a credit card during signup. They charge **$1 for verification** (refunded). Keep an eye on the email account you use — they send confirmations and alerts there.

## Why all this ceremony

You could create an AWS account, copy your root user's access keys, paste them into the CLI, and start working in 5 minutes. **Don't.**

The root user has **unlimited permissions over your entire account, including billing and account closure.** If those credentials leak — committed to a public repo, copied in a screen share, in a malware-infected machine — someone can run up a $10,000 bill on your card before you wake up. AWS will not refund that.

The right setup — IAM user with limited permissions + MFA on root + budget alerts — takes 40 minutes once and protects you forever. Treat this guide as non-skippable.

---

## Step 1 — Create the AWS account

1. Go to **<https://aws.amazon.com/>** and click **"Create an AWS Account"** (top right).
2. Email: use a real email you check daily. AWS sends important notifications here.
3. Account name: `marianela-portfolio` (or similar). This is just a label, not a username.
4. Click "Verify email address". Check your inbox, paste the 6-digit code.
5. Set a strong root password. **Save it in your password manager**, you'll rarely use it but you must not lose it.
6. Account type: **Personal**.
7. Fill in your name, address, phone — must match what's on your credit card.
8. Credit card: enter the details. AWS charges **$1 for verification, refunded within a few days**.
9. Phone verification: AWS calls or texts a code. Enter it.
10. Support plan: choose **Basic Support — Free**. (Developer/Business plans cost $29+/month, you don't need them.)
11. Sign in to the AWS Console as **Root user** with the email + password you just set.

You should land on the AWS Management Console homepage. You're in.

> **Important:** in the top-right corner, you can choose your **region**. For this project, set it to **`eu-west-1` (Ireland)** or **`eu-central-1` (Frankfurt)** since you're in Madrid — closer = lower latency and you stay within EU data residency rules. **Decide once and stick to it** for this project; switching region later means re-creating buckets and resources.

I'll assume `eu-west-1` for the rest of these guides. If you choose a different one, replace `eu-west-1` mentally everywhere.

## Step 2 — Activate MFA on the root user

MFA = "Multi-Factor Authentication". Even if your password leaks, an attacker can't log in without your phone.

**Use a software authenticator** (Google Authenticator, Authy, Microsoft Authenticator, 1Password — any of them). Hardware keys (YubiKey) are more secure but overkill for portfolio.

1. Top-right of the AWS Console, click your account name → **Security credentials**.
2. Section **"Multi-factor authentication (MFA)"** → click **"Assign MFA device"**.
3. Device name: `marianela-phone` (just a label).
4. Select **Authenticator app**, click Next.
5. AWS shows a QR code. Open your authenticator app on your phone, tap "Add account" / "+", scan the QR.
6. Your app now shows a 6-digit code that changes every 30 seconds.
7. Enter the **current code** as "MFA code 1", wait 30 seconds for the next one, enter it as "MFA code 2".
8. Click **Add MFA**.

From now on, every time you log in to the Console as root, AWS will ask for the MFA code.

**Test it:** sign out (top-right → Sign out), sign in again as root. You'll be asked for the code.

---

## Step 3 — Create an IAM user for daily work

Now we create a "regular" user that you'll use for everything from now on. The root user goes back in the drawer.

1. In the AWS Console, top search bar, type `IAM`, click the IAM service.
2. Left sidebar → **Users** → **Create user**.
3. **User name:** `olist-portfolio-dev`.
4. **Tick** "Provide user access to the AWS Management Console" — yes, you want a console password too.
5. **Console password:** "Autogenerated password". Tick "Users must create a new password at next sign-in".
6. Click **Next**.

### Permissions

This is where we get specific. The root user does everything; this user should only do what the project needs.

7. **Permissions options** → choose **"Attach policies directly"**.
8. In the search box, find and tick the following AWS-managed policies:
   - `AmazonS3FullAccess`
   - `AWSGlueConsoleFullAccess`
   - `AmazonAthenaFullAccess`
   - `AWSLambda_FullAccess`
   - `AmazonEventBridgeFullAccess`
   - `IAMReadOnlyAccess` ← read-only on IAM, you'll use root for IAM writes
   - `AWSBudgetsActionsWithAWSResourceControlAccess`
   - `CloudWatchLogsFullAccess`
9. Click **Next**, **Next**, **Create user**.

> **Honest disclaimer:** these AWS-managed policies are *broader than strictly needed*. In a production setup we'd write a custom policy that allows actions only on resources tagged `project=olist-pipeline`, with explicit Deny statements blocking the rest. We're skipping that for portfolio because:
> 1. The blast radius is your own dev account, not a company prod.
> 2. Writing scoped IAM policies is a 4-hour task that doesn't go in the dashboard.
> 3. The point of portfolio is the BI/data work, not IAM mastery.
>
> If a recruiter asks "would you do this in production?" the honest answer is no, and you can describe the scoped-policy approach. That's a separate ADR if you want to write it.

### Save the auto-generated password

10. After creation, AWS shows you the console password **once**. **Save it in your password manager NOW.**
11. **Sign-in URL** for IAM users looks like `https://<account-id>.signin.aws.amazon.com/console`. Save this URL too — you'll log in here, not via the regular AWS homepage.

### Test logging in as the IAM user

12. Sign out from root.
13. Open the IAM sign-in URL from step 11.
14. User name: `olist-portfolio-dev`. Password: the auto-generated one.
15. AWS will force you to set a new password — do it, save the new one in your password manager.

You're now logged in as `olist-portfolio-dev`. **From now on, this is your daily-driver login.** Don't use root unless you specifically need to (creating IAM users, billing settings, account closure).

## Step 4 — Activate MFA on the IAM user too

Same procedure as Step 2, but logged in as `olist-portfolio-dev`:

1. Top-right, your IAM username → **Security credentials**.
2. **Multi-factor authentication (MFA)** → **Assign MFA device**.
3. Use the same authenticator app, but **add a second account** (don't overwrite the root one). Name it `marianela-iam` to distinguish.
4. Same QR-scan-2-codes flow as before.

Now both root and `olist-portfolio-dev` have MFA. Two separate codes in your authenticator app.

## Step 5 — Create access keys for the CLI

Access keys are the credentials the AWS CLI uses (separate from your console password).

1. Logged in as `olist-portfolio-dev`, top-right → **Security credentials**.
2. Section **"Access keys"** → **Create access key**.
3. AWS shows a warning about best practices. Use case: **"Command Line Interface (CLI)"**.
4. Tick the confirmation, click **Next**.
5. Description tag (optional): `olist-portfolio-laptop`.
6. Click **Create access key**.

AWS shows you:
- **Access key ID** (starts with `AKIA...`) — like a username.
- **Secret access key** (long random string) — like a password. **Shown only once.**

7. Click **"Download .csv file"** to save them safely. Move that CSV to your password manager and **delete the file from your Downloads folder.**

> **Critical:** if you ever commit `AKIA...` strings to git, **GitHub will detect them within minutes** and AWS will alert you. Treat them like a credit card number.

## Step 6 — Configure AWS CLI

Open PowerShell.

```powershell
aws configure --profile olist-portfolio
```

Paste in:
- **AWS Access Key ID:** `AKIA...` from Step 5.
- **AWS Secret Access Key:** the long string from Step 5.
- **Default region name:** `eu-west-1` (or whatever you chose in Step 1).
- **Default output format:** `json`.

This stores the credentials in `C:\Users\<you>\.aws\credentials` and the config in `C:\Users\<you>\.aws\config`, under a profile named `olist-portfolio`.

### Verify it works

```powershell
aws sts get-caller-identity --profile olist-portfolio
```

Expected output (JSON):

```json
{
    "UserId": "AIDA...",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/olist-portfolio-dev"
}
```

If you see your IAM user's ARN, **you're done with the CLI setup**.

If you get `Unable to locate credentials`, the profile name didn't match. Try `aws configure list-profiles` to see what's configured.

### Make `olist-portfolio` the default for this terminal session

Instead of typing `--profile olist-portfolio` on every command, set it once:

```powershell
$env:AWS_PROFILE = "olist-portfolio"
```

This lasts only for the current PowerShell session. To make it permanent for this project, we'll set it in the project's `.env` file in the next guide.

```powershell
aws sts get-caller-identity   # no --profile needed now
```

## Step 7 — Set up budget alerts

This is the **single most important step against cost surprises.** Three email alerts at $5, $20, $50.

You can do it via the Console, but the CLI is faster and reproducible. Here's the inline version (we'll later put this in `infra/budgets.sh` for reproducibility):

```powershell
# Replace with YOUR account ID and YOUR email.
$ACCOUNT_ID = "123456789012"
$EMAIL = "fernandezmarianeladp@gmail.com"

# Three budgets, identical structure, different thresholds.
foreach ($threshold in 5, 20, 50) {
    $name = "olist-budget-$threshold"
    $budget = @{
        BudgetName = $name
        BudgetLimit = @{ Amount = "$threshold"; Unit = "USD" }
        TimeUnit = "MONTHLY"
        BudgetType = "COST"
        CostFilters = @{ TagKeyValue = @("user:project`$olist-pipeline") }
    } | ConvertTo-Json -Depth 5

    $notification = @{
        Notification = @{
            NotificationType = "FORECASTED"
            ComparisonOperator = "GREATER_THAN"
            Threshold = 100
            ThresholdType = "PERCENTAGE"
            NotificationState = "ALARM"
        }
        Subscribers = @(
            @{ SubscriptionType = "EMAIL"; Address = $EMAIL }
        )
    } | ConvertTo-Json -Depth 5

    $budget | Out-File -Encoding utf8 budget.json
    $notification | Out-File -Encoding utf8 notif.json

    aws budgets create-budget `
        --account-id $ACCOUNT_ID `
        --budget file://budget.json `
        --notifications-with-subscribers file://notif.json

    Remove-Item budget.json, notif.json
}
```

> **What this does:** for each of $5, $20, $50, creates a monthly budget filtered by tag `project=olist-pipeline`, with an email alert when forecasted cost exceeds 100% of the budget.

> **`FORECASTED`** means AWS sends you an alert when the *projected end-of-month* cost will exceed the threshold — not when you've already spent it. That gives you reaction time.

To get your account ID:

```powershell
aws sts get-caller-identity --query Account --output text
```

### Verify the budgets exist

```powershell
aws budgets describe-budgets --account-id <YOUR_ACCOUNT_ID> --query "Budgets[].BudgetName"
```

Should output:

```json
[
    "olist-budget-5",
    "olist-budget-20",
    "olist-budget-50"
]
```

### Test the alert

You can't really test it without provisioning expensive resources. Just trust it: the day you accidentally spin up something that costs $5+/month forecasted, you'll get an email within 24 hours.

## Sanity check

```powershell
# 1. CLI is configured
aws sts get-caller-identity --profile olist-portfolio

# 2. Budgets are in place
aws budgets describe-budgets --account-id <YOUR_ID> --query "Budgets[].BudgetName"

# 3. Default region is correct
aws configure get region --profile olist-portfolio
# expected: eu-west-1
```

All three should return real data. If yes, you're done.
